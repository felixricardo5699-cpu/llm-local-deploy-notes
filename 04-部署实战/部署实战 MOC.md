# 部署实战 MOC

> [!abstract] 一句话讲清楚
> 这个文件夹只回答一个问题：**怎么把"模型能跑"变成"客户能用"**。前面几章是零件，这里是装配线，最后还给你一张出厂检验单。

## 这个领域在技能栈里的位置

- **上游**：[[基础底座 MOC]] 决定机器和系统能不能撑住、[[推理引擎选型决策树]] 决定用哪个引擎跑。
- **本领域**：把"摸硬件 → 选模型 → 选引擎 → 起服务 → 验收到交付"串成一条**可以重复执行的流程**，并沉淀成清单。
- **下游**：[[RAG 原理与全链路]] 等应用集成是"用这个服务做什么"；[[交付 SOP 与报价]] 等工程化是把这件事变成生意。

说白了：模型认知和推理引擎教你"为什么这样选"，部署实战教你"这次具体怎么干、干到哪算完"。

## 核心名词全解（8 个就够看懂这个领域）

| 名词 | 英文/缩写 | 大白话解释 | 容易混淆/注意 |
|---|---|---|---|
| 推理服务 | Inference Server | 把模型加载进显存、对外提供 API 的常驻程序 | 和"模型文件"不是一回事，服务挂了模型还在 |
| 权重 | Weights | 模型学到的参数文件，通常几十 GB | 量化后的权重更小，效果略有损失 |
| 量化 | Quantization | 用更低精度存权重，换显存和速度 | 4bit 不是"无损"，别向客户承诺效果不变 |
| 上下文长度 | Context Length | 一次对话能塞进去的最大 token 数 | 设得越大越吃显存，不是白拿的 |
| 并发 | Concurrency | 同一时刻同时处理的请求数 | 不等于"在线人数"，一个人也可能连发 |
| 首字延迟 | TTFT | 从发问到出第一个字的时间 | 和"总生成速度"是两个指标 |
| 常驻服务 | Daemon | 关掉终端、重启机器后仍在跑的后台进程 | 前台跑个脚本不算部署 |
| 验收标准 | Acceptance Criteria | 双方事先约好"怎样算交付完成" | 口头说的不算，要写进确认单 |

## 一张图看清整条链路

```mermaid
flowchart LR
  A["① 摸硬件"] --> B["② 选模型档位"]
  B --> C["③ 选引擎"]
  C --> D["④ 装环境"]
  D --> E["⑤ 拉/搬模型"]
  E --> F["⑥ 起服务"]
  F --> G["⑦ 验证"]
  G --> H["⑧ 接客户端"]
  H --> I["⑨ 压测"]
  I --> J["⑩ 交付"]
```

三条主线同时进行，别只盯一条：

1. **算力线**：显卡/内存够不够，决定模型档位和量化等级。
2. **模型线**：用什么格式、从哪拿、怎么搬、怎么校验。
3. **服务线**：怎么起、怎么鉴权、怎么让客户端稳定连上。

## 最容易翻车的三个地方

- **跳过"摸硬件"直接抄别人命令**：别人 24G 显存跑得欢，你 8G 直接 OOM，折腾一整天。
- **把"能对话"当成"部署完"**：客户要的是并发、稳定、鉴权、重启自恢复，这些是服务化的事。
- **没有验收标准**：交付时双方对"好了没有"各说各话，返工和尾款都难受。

## 和 08-工程化交付 的分工

- 本文夹走"**首次落地**"：从裸机到能用的服务。
- [[容器化部署]]、[[监控与日志]]、[[远程交付与远程运维]] 走"**长期运维**"：把这次落地变成可复制、可远程维护的产品。
- 同一个客户第二次部署时，你应该开始套用 08 的东西，而不是再手工来一遍。

## 决策点：本领域的三个岔路口

- **现象**：客户机器配置说不清｜**判断依据**：显存、内存、系统、外网四样至少缺一样｜**推荐**：先发摸底问题单，拿到截图再报价｜**代价**：慢半天，但避免返工和退款。
- **现象**：模型"能对话"了，客户说要给同事一起用｜**判断依据**：使用者多于一个人｜**推荐**：走服务化（常驻/鉴权/限流）并压测后再交｜**代价**：工期多半天到一天，避免上线第二天崩。
- **现象**：客户只有内网，模型又大｜**判断依据**：能否联网下载、硬盘和介质够不够｜**推荐**：离线搬运 + 两侧校验，提前算好介质容量｜**代价**：可能要跑一趟现场或寄硬盘，工期变长但可控。
- **现象**：客户要求"一周让几十个人用上"｜**判断依据**：硬件余量与模型档位是否匹配｜**推荐**：先压测给出真实并发上限，把边界写进确认单｜**代价**：可能劝退一部分预期，但口碑和安全都保住。

## 交付视角（对客户怎么讲）

- 客户问"多久能装好"：先给**检查清单式的摸底问题**（机器什么配置、有没有外网、谁来用），再说时间。别一上来报"两小时搞定"。
- 客户问"装完是不是就完事了"：把本篇的十步当"交付范围"讲清楚——我们交付的是**服务 + 验收单 + 使用说明**，不是"帮你装了个软件"。
- 客户问"为什么还要压测"：压测是把"能用"和"多少人同时能用"分开，避免上线第一天就被同事一起用崩。
