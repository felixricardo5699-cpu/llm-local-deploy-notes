# 模型谱系 GLM 与 Gemma

> [!abstract] 一句话讲清楚
> GLM（智谱）和 Gemma（Google）是两条"非 Qwen、非 DeepSeek"的开源路线：GLM 中文和中文场景适配扎实、长上下文版本多；Gemma 轻量、多模态、端侧友好。它们的**共同特点是许可证都不是标准 Apache-2.0**，商用前必须单独看条款。

## 为什么重要

- 选型时不能只盯两家。客户可能有品牌偏好、可能有合规要求、也可能就是要"一个小而能看图的模型"——这两条线正好补位。
- **许可证是这两家最需要注意的地方**：GLM 和 Gemma 都用自己的许可协议，允许商用但带条件（登记、使用限制、再分发条款等）。搞错这一条，交付出去的文件可能不合规，见 [[开源许可证与合规]]。
- 部署侧的价值：
  - Gemma 小尺寸 + 多模态，适合端侧、Mac、低显存机器；
  - GLM 有偏中文和长上下文的型号，适合文档、政企场景。
- 这篇同样**不背版本号**，讲"怎么看模型卡、怎么判断适用"。

## 核心名词全解

| 名词 | 英文 / 缩写 | 大白话解释 | 容易混淆 / 注意 |
|---|---|---|---|
| GLM 系列 | GLM (Zhipu) | 智谱开源的大模型线，有文本、视觉、长上下文等变体。 | 名字来自 General Language Model，不是"通用大模型"的缩写直译。 |
| Gemma 系列 | Gemma (Google) | Google 开源的轻量模型线，起点是"从 Gemini 体系下放的小模型"。 | 和 Gemini 不是一回事，Gemma 是开权重版本。 |
| 尺寸档位 | Size Tier | 同代里按参数量分小/中/大档。 | 两家都比 Qwen 的档位粗，选择余地小一些。 |
| 视觉版 | VL / Vision | 能处理图片输入的版本。 | 需要额外的视觉编码器开销，见 [[多模态模型原理]]。 |
| 长上下文版 | Long Context | 专门优化过长输入的版本。 | "支持"和"用得好"是两回事，见 [[上下文窗口与位置编码]]。 |
| 开源权重 | Open Weights | 权重能下载，但**不等于** OSI 意义的开源。 | 这是理解许可证的关键区别。 |
| 自定义许可 | Custom License | 厂商自己写的使用协议，不是 Apache/MIT。 | 常见形式：允许商用但需登记、有使用限制、要求保留声明。 |
| 商用登记 | Registration | 有的协议要求"商用前登记/告知"。 | 忘了登记是合规风险，不是技术问题。 |
| 禁止用途 | Prohibited Use | 协议里明确禁止的场景（如某些违法/武器用途）。 | 给客户交付时要提醒不能用于这些场景。 |
| 再分发 | Redistribution | 把模型文件/衍生模型再发给第三方。 | 打包进客户机器属于交付，条款要看清。 |
| 端侧 | On-device / Edge | 小到能在手机、笔记本、嵌入式上跑。 | Gemma 小档位是典型代表。 |
| 模型卡 | Model Card | 官方说明结构、能力、许可的页面。 | 一切以模型卡和 LICENSE 为准。 |

## 原理与机制

### 两条线各自的定位

| 维度 | GLM 系列 | Gemma 系列 |
|---|---|---|
| 出身 | 国内厂商，中文语料与中文场景打磨多 | Google，走"轻量 + 多模态 + 端侧"路线 |
| 强项 | 中文理解、长上下文版本、政企场景适配 | 小尺寸效率、多模态、跨设备部署 |
| 尺寸档位 | 中小到中大档 | 偏小、中档，大档也有 |
| 多模态 | 有视觉变体 | 有多模态版本 |
| 生态 | 国内社区、部分国产芯片适配较好 | 国际工具链支持好（llama.cpp/Ollama 等） |
| 许可 | 自定义协议，偏商用友好但带条件 | 自定义使用条款，允许商用但有限制 |

### GLM 怎么理解

- 它是**国内较早做开源的一批**，中文语料覆盖比较好，理解中文里的"潜台词"和行业黑话相对顺。
- 变体结构可以按"文本 / 视觉 / 长上下文"三条支线理解，具体命名以官方仓库为准。
- 对交付的意义：**中文客服、中文文档问答、政企内网项目**是它的舒适区；如果客户对中文表达自然度很敏感，值得拿来对比测试。
- 它的开源协议里通常有"商用需遵守条款/可能需要登记"之类的内容——**看到"开源"两个字不能直接当成"随便商用"**。

### Gemma 怎么理解

- 它的定位是"**把大模型能力压缩到能跑在普通设备上**"。小档位可以跑在笔记本、甚至手机级别的算力上。
- 多模态版本让"看图说话"这件事能在低显存设备上做，这是它相对其他小模型的差异化。
- 生态上，它被 llama.cpp / Ollama 等主流本地推理工具广泛支持，`GGUF` 格式文件很容易找，见 [[llama.cpp 与 GGUF]]。
- 许可上，它用的是 Google 自己的使用条款：**允许商用，但有明确的使用限制**，并且对再分发、声明保留有要求。具体条款随版本更新，**以官方 LICENSE 为准**。

> [!warning] 这里的共同雷区
> "开源模型"这个词在中文里被用得很随意。严格说：
> - **Apache-2.0 / MIT**：OSI 认可的开源许可，商用限制最少；
> - **Llama 社区许可 / Gemma 条款 / GLM 协议**：**开放权重**，但协议自定义，商用有附加条件；
> - 交付前必须把 LICENSE 原文过一遍，别只看 README 的一句"可免费商用"。

### 为什么许可证会影响部署方案

不是"技术问题"会卡在"合同问题"上：

- 客户是**甲方企业**，法务会要一份"合规说明"；
- 你把模型打包进客户的离线服务器 → 算**交付和再分发**；
- 你把模型做成 SaaS 对外服务 → 通常另有条款（有的协议限制托管服务）；
- 客户要**对外宣称基于某模型** → 可能涉及商标和声明要求。

所以选型时要把"许可"和"性能"放在同一张表里比，见 [[开源许可证与合规]]。

## 分类与对比

### GLM 与 Gemma 的适用判断

| 场景 | 推荐 | 理由 |
|---|---|---|
| 中文客服 / 中文文档问答 | GLM 系列 | 中文表达和行业词更自然 |
| 政企内网、国产化要求 | GLM 系列 | 国内生态与适配更成熟 |
| 笔记本 / Mac 本地跑 | Gemma 小档 | 尺寸小、量化资源多 |
| 低显存 + 要看图 | Gemma 多模态小档 | 小尺寸多模态是它的差异化 |
| 需要极强通用能力 | 优先考虑 Qwen / DeepSeek 的中大档 | GLM/Gemma 在超大档上选择少 |
| 对许可极敏感（要 Apache/MIT） | 都慎用，先查条款 | 这两家都是自定义协议 |

### 三条开源线的粗对比

| 维度 | Qwen 系列 | DeepSeek 系列 | GLM / Gemma |
|---|---|---|---|
| 尺寸档位密度 | 极高 | 偏低（偏大） | 中等 |
| 中文能力 | 强 | 强 | GLM 强；Gemma 一般 |
| 多模态 | 有 | 较少 | 两家都有 |
| 端侧友好 | 有 | 一般 | Gemma 突出 |
| 许可友好度 | 多数宽松 | 部分很宽松 | 均需看自定义条款 |
| 社区量化资源 | 最多 | 多 | 中等 |

## 决策点

- **岔路口 1：客户明确要求中文体验最好**
  - 判断依据：拿 20~30 条真实中文业务问题做盲测。
  - 推荐选择：**Qwen 与 GLM 各拉一版对比**，按实测选，不要凭印象。
  - 代价：多一轮压测工时，但返工风险大幅下降。

- **岔路口 2：客户要"低配机器 + 能看图"**
  - 判断依据：显存是否 ≤ 12G~16G，是否需要 OCR/截图理解。
  - 推荐选择：**Gemma 多模态小档 + int4**，或 Qwen 的小尺寸 VL 版。
  - 代价：小模型看图能力有限，复杂图表/密集文字会不准。

- **岔路口 3：客户法务要"无附加条件的开源许可"**
  - 判断依据：客户能否接受自定义协议。
  - 推荐选择：**优先 Apache-2.0 / MIT 的模型**；如果必须用 GLM/Gemma，出具 LICENSE 说明并由客户法务确认。
  - 代价：候选模型范围缩小，可能牺牲效果。

- **岔路口 4：要不要在内网做"再分发"（打包给客户）**
  - 判断依据：协议是否允许再分发、是否要求保留声明。
  - 推荐选择：**保留完整 LICENSE 与声明文件随模型一起交付**，并在合同里写清"模型许可由原厂商提供，乙方不改变其条款"。
  - 代价：交付物多几份文件，但能规避合规风险。

## 参数与配置说明

| 参数 | 作用 | 调大/调小的影响 | 常见取值 |
|---|---|---|---|
| 尺寸档位 | 参数量级 | 越大越强越吃显存 | 按显存档位选 |
| 变体（文本/视觉/长上下文） | 决定能力范围 | 选错白买硬件 | 按业务定 |
| 量化档位 | 精度 | 影响显存和质量 | int4 / int8 |
| 上下文长度 | 长文本上限 | 影响 KV 与延迟 | 按业务定 |
| 视觉输入分辨率 | 图片精度 | 越高越吃显存 | OCR 场景要够高 |
| 部署框架 | llama.cpp / vLLM 等 | 影响并发和速度 | 见 [[推理引擎选型决策树]] |
| 许可声明文件 | 合规要求 | 缺了有风险 | 交付时必须带 |

## 常见坑与误区

| 现象 | 原因 | 对策 |
|---|---|---|
| 看到 README 写"可免费商用"就直接用 | README 不等于 LICENSE 全文 | 逐条看 LICENSE，保留原文随交付 |
| 把"开源权重"当成 OSI 开源 | 开放权重和开源许可是两回事 | 用"开放权重"表述，别对客户说"完全开源随便用" |
| 打包给客户时删掉了 LICENSE 文件 | 再分发条款要求保留声明 | 交付清单里固定包含 LICENSE |
| 以为 Gemma 只能跑在 Google 生态 | 它被 llama.cpp/Ollama 广泛支持 | 用 GGUF 就能在本地跑 |
| 把 GLM 当成"只能中文" | 它也有多语言能力 | 按实测判断，不要贴标签 |
| 小尺寸多模态拿去读密集表格 | 小模型视觉分辨率有限 | 提高分辨率或改用 OCR + 文本模型组合 |
| 拿不同代的同档位直接比 | 代际差异可能大于尺寸差异 | 比之前确认是同一代、同量化档 |
| 忽略"禁止用途"条款 | 协议里有明确黑名单 | 交付时书面提示客户使用边界 |

## 案例拆解：两个真实取舍

**案例一：政企中文知识库，要求私有化**

- 需求：中文问答、内网部署、客户明确说"最好用国内的模型"。
- 判断：中文体验优先 + 品牌偏好明确的场景，GLM 是天然候选。
- 做法：拿 GLM 的中档和 Qwen 的中档各部署一版，用 30 条真实业务问题盲测（打分的是客户业务人员，不是工程师）。
- 结果处理：谁好用说谁好，如果 GLM 在中文表达上更自然，就选它；然后把它的自定义许可条款整理成一页纸交法务。**别因为"性能强一点点"就忽略许可成本**——政企项目法务审得很细。

**案例二：笔记本上跑一个"能看图"的助手**

- 需求：个人或小团队，Mac/Windows 笔记本，离线跑，要能看截图回答问题。
- 判断：尺寸必须小，量化必须狠，多模态要选小档。
- 做法：Gemma 的多模态小档 + int4，配 llama.cpp/Ollama 跑，先测"看得懂大概"，再测"读得准不准"。
- 结果处理：截图问答能用，但**密集文字和小字识别要提前跟客户打招呼**，别承诺 OCR 级精度。真要做精确提取，加一个专用 OCR。

两个案例的共同点：**先按"场景 + 硬件"筛出两三个候选，再用客户自己的数据盲测，最后过许可关。**

## 常识补丁：这三个说法容易得罪人

- 别说"Gemma 是 Gemini 的开源版"——Gemma 是独立发布的开放权重模型，不是 Gemini 开源。
- 别说"GLM 只能中文"——它有多语言能力，只是中文场景打磨更多。
- 别说"开源模型就等于免费商用"——这两家的协议都允许商用但带条件，"免费"和"无限制"是两件事。

## 部署检查：跑这两家模型前要确认的五件事

| 检查项 | 为什么 | 怎么确认 |
|---|---|---|
| 模型文件格式 | 有的权重是原生格式，得转换才能用 | 看官方仓库提供的格式，优先找 GGUF 或引擎直接支持的格式 |
| 引擎是否支持该架构 | 新架构在旧版 llama.cpp/vLLM 里可能加载失败 | 看引擎 release 说明，必要时升级 |
| 上下文长度设置 | 默认值往往远小于宣称值 | 启动参数里显式指定，别指望自动 |
| 量化文件来源 | 第三方量化档质量参差不齐 | 优先官方或高信誉发布者，见 [[量化技术]] |
| 许可声明文件 | 合规要求 | 随模型一起保留，别在搬文件时删掉 |

还有一个实操细节：**这两家的模型在国内下载可能比 Qwen 慢**，离线交付场景要提前准备好文件（见 [[模型获取与离线搬运]]），别到客户现场才发现下不动。

## 交付视角（对客户怎么讲）

- **客户问"这两个模型能商用吗"**：标准回答——"**能商用，但它们用的是厂商自定义许可，不是 Apache 那种通用开源协议；商用有附加条件（比如保留声明、部分用途限制）。我会把 LICENSE 原文和合规说明一起放进交付物，建议你们法务过一遍。**"这句话既专业又免责。
- **客户问"为什么不用大家最常说的那两个"**：给理由——"**你要低配看图 / 你要中文最自然 / 你要求特定许可，所以这两条线更合适**"。选型讲"匹配"，不讲"最强"。
- **报价要点**：GLM/Gemma 的部署成本不高，但**合规审查和文档工时**要算进去。很多单子最后卡在法务而不是技术。
- **写进方案**：固定写"模型名称 + 许可类型 + 合规说明 + 再分发约定"四项。
- **别承诺**：不要说"这是完全开源、没有任何限制"。说过头了，客户法务一查，信任直接崩。
