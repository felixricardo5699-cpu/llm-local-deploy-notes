# 学习路线图

> [!abstract] 一句话讲清楚
> 把"学会这套技能栈"拆成 **5 个阶段**，每个阶段有明确的**能力验收标准**——不是"看完笔记"，而是"能做到某件事"。周级别的执行表见 [[8 周学习计划]]，这里给的是阶段能力地图。

---

## 一、先明确：你要学到哪一档

| 档位 | 目标 | 需要走完的阶段 | 时间（有编程基础） |
|---|---|---|---|
| **A. 自用** | 在自己电脑上跑模型、搭知识库、画图 | 阶段 0~2 + 部分 3 | 3~4 周 |
| **B. 接单**（本库默认） | 能给客户做部署、知识库、ComfyUI，能报价交付 | 阶段 0~5 | 3~5 个月 |
| **C. 行业深耕** | 微调、多卡、复杂企业架构 | 阶段 0~5 + 专项深挖 | 6 个月以上 |

> [!tip] 别一上来学微调
> 阶段顺序是有原因的：不会算显存就去学微调，等于不会算材料就去盖楼。而且从变现速度看，部署/知识库/ComfyUI 的订单远多于微调订单。

---

## 二、阶段 0：认知对齐（约 1 周）

**目标**：建立全局地图，知道这套东西由哪几块组成、大致怎么串起来。

| 学习内容 | 笔记 |
|---|---|
| 全局结构 | [[技能栈总览 MOC]]、[[README 从这里开始]] |
| 名词扫盲 | [[术语总表]] |
| 三层能力模型 | [[技能栈总览 MOC]] 第四节 |

**验收标准**（能用自己的话说出来）：

- [ ] 能说出 8 个领域各自解决什么问题
- [ ] 能解释"参数量、显存、量化、上下文长度"之间的关系
- [ ] 能说出至少 3 种推理引擎和它们分别适合什么场景

**常见卡点**：一上来就找教程开装。**先建立地图，再动手**，否则装完也不知道自己在装什么。

---

## 三、阶段 1：能跑起来（约 2~3 周）

**目标**：能在自己/客户的机器上，把指定模型跑成一个可用的 API 服务。

| 学习内容 | 笔记 |
|---|---|
| 硬件与系统底座 | [[硬件基础与 GPU 生态]]、[[驱动-CUDA-框架版本兼容]]、[[Linux 基础与服务器操作]] |
| 会不会算账 | [[参数量与显存估算]]、[[量化技术]] |
| 模型与引擎 | [[Ollama]]、[[llama.cpp 与 GGUF]]、[[推理引擎选型决策树]] |
| 完整流程 | [[本地部署全流程]]、[[部署检查清单]] |
| 对外接口 | [[OpenAI 兼容 API 规范]]、[[客户端 UI 工具]] |

**动手项目**：见 [[项目阶梯与实战清单]] 项目 1~2。

**验收标准**（必须真实跑通，不能只在脑子里过）：

- [ ] 看一台机器的显卡型号和显存，能在 1 分钟内判断"能跑多大参数量的什么量化档"
- [ ] 独立完成一次"装引擎 → 拉模型 → 起服务 → 用客户端连上"的完整流程
- [ ] 能解释 `-ngl`、`gpu-memory-utilization`、`max-model-len` 这类关键参数在干嘛
- [ ] 遇到 OOM 能判断是权重太大还是上下文太长

**常见卡点**：
- 卡在驱动/CUDA 版本 → 看 [[驱动-CUDA-框架版本兼容]]
- 卡在模型下载 → 看 [[模型获取与离线搬运]]
- 卡在 OOM 不会算 → 回 [[参数量与显存估算]]

## 四、阶段 2：会选型、会调优（约 2 周）

**目标**：从"能跑"升级到"会选、会调、会排错"——这一阶段决定了你比"看教程的人"贵多少。

| 学习内容 | 笔记 |
|---|---|
| 引擎深入对比 | [[vLLM]]、[[Ollama]]、[[llama.cpp 与 GGUF]]、[[SGLang 与 TensorRT-LLM]] |
| 性能与调优 | [[推理性能指标与调优]]、[[性能调优清单]] |
| 上下文与采样 | [[上下文窗口与位置编码]]、[[采样参数与解码策略]] |
| 排错 | [[排错方法论]]、[[故障案例库]] |

**动手项目**：同一个模型用两种引擎各跑一次，记录首字延迟和吞吐，做成对比表。

**验收标准**：

- [ ] 能解释首字延迟（TTFT）和吞吐（tokens/s）的区别，以及它们为什么冲突
- [ ] 给定"10 人并发"和"单机自用"两种需求，能给出不同的引擎方案
- [ ] 效果不好时能区分"是模型不行、还是量化损失、还是参数设置问题"
- [ ] 能用分层法定位一个新出现的报错

**常见卡点**：只看不测。**必须压测出数字**，否则你永远不知道参数调了有没有效果。

## 五、阶段 3：能接入应用（约 3~4 周）

**目标**：把裸模型变成"客户能用的东西"。这里开始分叉，按你的客户类型选一条先走。

### 分支 A：RAG / 知识库（订单最多）

| 学习内容 | 笔记 |
|---|---|
| 全链路 | [[RAG 原理与全链路]] |
| 解析与切分 | [[文档解析与切分策略]] |
| 向量与检索 | [[Embedding 与向量数据库]]、[[检索与 Rerank]] |
| 评估调优 | [[RAG 评估与调优]] |
| 平台落地 | [[Dify 平台与工作流]] |

**验收标准**：能搭一个 20 份文档以上的知识库，准备 30 个问题做评测，能说出"哪些没答对、为什么、怎么改"。

### 分支 B：ComfyUI 图像/视频（单价最高）

| 学习内容 | 笔记 |
|---|---|
| 原理 | [[扩散模型原理]] |
| 工具 | [[ComfyUI 核心概念]]、[[ComfyUI 工作流实操]] |
| 模型生态 | [[模型目录与生态]]、[[文生图模型生态]]、[[图生视频模型生态]] |
| 低显存优化 | [[低显存工作流优化]] |
| 控制 | [[ControlNet 与 LoRA]] |

**验收标准**：能在 8G 显存机器上跑通一套文生图工作流 + 一套短视频工作流，并能解释每一步节点在干嘛。

### 分支 C：Agent / 自动化干活

| 学习内容 | 笔记 |
|---|---|
| 接口与协议 | [[OpenAI 兼容 API 规范]]、[[Agent 与 Function Calling]]、[[MCP 协议]] |
| 接入壳 | [[本地模型接入编码助手]] |
| 上下文管理 | [[提示词与上下文工程]] |

**验收标准**：让本地模型通过编码助手壳完成一个多步任务，并能排查"模型不调用工具"这类问题。

**常见卡点**：RAG 效果差就换模型（错，多半是切分/检索问题）；ComfyUI 从空白节点搭（错，要从模板改）。

## 六、阶段 4：微调（约 1~2 个月，可选）

**目标**：客户拿私有数据来了，你能判断"该微调还是该 RAG"，并且能走完闭环。

| 学习内容 | 笔记 |
|---|---|
| 先做判断 | [[微调决策与 RAG 取舍]] |
| 数据 | [[训练数据工程]] |
| 原理与参数 | [[LoRA 与 QLoRA 原理]]、[[训练超参数]] |
| 框架 | [[微调框架生态]] |
| 评估 | [[训练监控与评估]] |
| 闭环 | [[合并导出与部署闭环]] |
| 多模态 | [[多模态微调]] |

**验收标准**：

- [ ] 拿到一个需求能判断：RAG / 微调 / 换模型 / 提示词，哪个才是对的
- [ ] 能用几百到几千条数据跑完一次 QLoRA，并且知道 loss 曲线什么算正常
- [ ] 能对比基座与微调后模型的差异（不是"感觉变好了"）
- [ ] 能把 LoRA 合并、量化、回填到推理引擎里部署出来

**常见卡点**：数据质量差还硬训；不做留出集评估；把"知识"当"能力"去微调。

## 七、阶段 5：能交付（贯穿，约 2 周集中补）

**目标**：从"技术能做"到"商业能交"。

| 学习内容 | 笔记 |
|---|---|
| 容器化 | [[容器化部署]] |
| 远程 | [[远程交付与远程运维]] |
| 监控 | [[监控与日志]] |
| 安全 | [[安全与合规]] |

**验收标准**：

- [ ] 能回答客户三个灵魂问题：能跑吗、多少钱、会不会泄密
- [ ] 有自己的故障案例库（≥10 条亲手解决的）

## 八、时间估算总表

| 阶段 | 内容 | 时间 | 累计 |
|---|---|---|---|
| 0 | 认知对齐 | 1 周 | 1 周 |
| 1 | 能跑起来 | 2~3 周 | 3~4 周 |
| 2 | 会选型会调优 | 2 周 | 5~6 周 |
| 3 | 接入应用（选 1~2 条分支） | 3~4 周 | 8~10 周 |
| 4 | 微调闭环（可选） | 4~8 周 | 3~5 个月 |
| 5 | 交付能力 | 2 周 | 3~5 个月 |

> [!note] 时间估算是"每天 2~3 小时有效投入"的口径
> 全职投入可以压缩约一半，但**阶段 1 和阶段 2 的动手时间不能压缩**——这两阶段是靠手指记住的，不是靠看会的。

---

## 九、三条建议（避免走弯路）

1. **每阶段必须有一个可展示的产出物**（一个 API、一张压测表、一套工作流）。没有产出物 = 没学会。
2. **遇到问题先自己定位到"层"再问人**。直接甩一句"报错了"，学不到东西。方法见 [[排错方法论]]。
3. **先把一条分支打穿，再补其他**。RAG / ComfyUI / 微调三条线同时学，大概率三条都半途而废。
