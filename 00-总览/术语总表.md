| Metal | — | 苹果的 GPU 计算接口，Mac 上跑模型的底层 | [[MLX 与 Apple 芯片推理]] |

## 二、模型架构

| 术语 | 英文 / 缩写 | 一句话解释 | 详见 |
|---|---|---|---|
| 参数量 | Parameters | 模型权重的数字个数，7B = 70 亿；决定"模型多大" | [[参数量与显存估算]] |
| Token | — | 模型处理的最小文本单位；中文大致 1 字 ≈ 1~2 token，是计费和上下文的单位 | [[Transformer 架构基础]] |
| 分词器 | Tokenizer | 把文本切成 token 的规则，**不同模型不通用** | [[Transformer 架构基础]] |
| 词表 | Vocabulary | 模型认识的全部 token 集合 | [[Transformer 架构基础]] |
| 嵌入 | Embedding | 把 token 变成向量的那层；RAG 里"文档转向量"也叫 embedding | [[Embedding 与向量数据库]] |
| Transformer | — | 当前所有主流大模型的基础架构，核心是注意力机制 | [[Transformer 架构基础]] |
| 注意力 | Attention | 让每个 token 去"看"其他 token 并加权，决定上下文怎么关联 | [[Attention 与 KV Cache]] |
| 多头注意力 | Multi-Head Attention | 多组注意力并行，分别抓不同维度的关系 | [[Attention 与 KV Cache]] |
| KV Cache | — | 推理时缓存历史 token 的 Key/Value 避免重算；**上下文越长它越吃显存** | [[Attention 与 KV Cache]] |
| GQA / MQA | Grouped / Multi Query Attention | 多个 Query 共享少量 KV 头，用来压缩 KV Cache | [[Attention 与 KV Cache]] |
| 前馈网络 | FFN | 注意力之后那层"思考区"，模型参数大头通常在这里 | [[Transformer 架构基础]] |
| 残差连接 | Residual | 让信息跨层直通，是深层网络能训起来的前提 | [[Transformer 架构基础]] |
| 位置编码 | RoPE | 告诉模型 token 的先后位置，决定上下文窗口能开多长 | [[上下文窗口与位置编码]] |
| 上下文窗口 | Context Window | 一次能"看到"的 token 上限，超了就截断或报错 | [[上下文窗口与位置编码]] |
| 稠密模型 | Dense | 每个 token 都要过全部参数，显存占用稳定可预测 | [[Dense 与 MoE 架构]] |
| 混合专家 | MoE | 只激活部分专家，总参数大但激活参数小；**显存仍按总参数算** | [[Dense 与 MoE 架构]] |
| 激活参数量 | Activated Params | MoE 每次推理真正用到的参数量，主要影响速度 | [[Dense 与 MoE 架构]] |
| 专家 | Expert | MoE 里并列的若干子网络，由路由器决定用哪几个 | [[Dense 与 MoE 架构]] |
| 推理模型 | Reasoning Model | 先做长思考再答的模型类型，慢但擅长数学/逻辑 | [[模型谱系 DeepSeek]] |
| 蒸馏 | Distillation | 用大模型的输出教小模型，得到"小但接近"的模型 | [[模型谱系 DeepSeek]] |
| 幻觉 | Hallucination | 模型一本正经编造内容；RAG 和评估主要就是收拾它 | [[RAG 原理与全链路]] |
| 训练 / 推理 | Training / Inference | 训练改权重，推理只用权重；本库 95% 场景是推理 | [[Transformer 架构基础]] |

## 三、量化与模型格式

| 术语 | 英文 / 缩写 | 一句话解释 | 详见 |
|---|---|---|---|
| 量化 | Quantization | 用低精度表示权重，用可接受的质量损失换显存和速度 | [[量化技术]] |
| FP16 / BF16 | — | 半精度，模型默认发布精度（约 2 字节/参数） | [[量化技术]] |
| FP8 | — | 8 位浮点，新卡支持好、损失小，图像与推理引擎常用 | [[量化技术]] |
| INT8 / INT4 | — | 整数精度，4 位最省显存，质量看量化方法 | [[量化技术]] |
| GGUF | GPT-Generated Unified Format | llama.cpp 生态的模型文件格式，单文件、自带量化档 | [[llama.cpp 与 GGUF]] |
| Q4_K_M | — | GGUF 量化档位命名：数字是位数，K 表示混合量化策略，M 是质量档 | [[llama.cpp 与 GGUF]] |
| AWQ | Activation-aware Weight Quantization | 面向 GPU 的 4bit 量化方法，vLLM 支持好 | [[量化技术]] |
| GPTQ | — | 另一套 GPU 4bit 量化方法，生态老牌 | [[量化技术]] |
| EXL2 | — | ExLlama 的量化格式，主打速度 | [[量化技术]] |
| safetensors | — | HuggingFace 的安全权重格式，原始精度，部署前通常要转换 | [[模型获取与离线搬运]] |
| 量化校准 | Calibration | 用样本数据决定量化参数的过程，直接影响量化质量 | [[量化技术]] |
| 混合量化 | Mixed Precision | 敏感层保高精度、其他层压低位 | [[量化技术]] |
| KV Cache 量化 | KV Quantization | 省的是"上下文"的显存，和权重量化不是一回事 | [[量化技术]] |
| 量化损失 | Quantization Loss | 量化后质量下降，表现为逻辑变差、格式错乱、长文崩 | [[量化技术]] |

## 四、推理与性能

| 术语 | 英文 / 缩写 | 一句话解释 | 详见 |
|---|---|---|---|
| 推理引擎 | Inference Engine | 真正执行模型计算的软件，Ollama / llama.cpp / vLLM 都是 | [[推理引擎选型决策树]] |
| Ollama | — | 包装好的一键式本地推理工具，上手最快，适合单机自用 | [[Ollama]] |
| llama.cpp | — | C++ 写的轻量推理引擎，CPU/GPU 混合，GGUF 生态核心 | [[llama.cpp 与 GGUF]] |
| vLLM | — | 面向生产的 Python 推理引擎，吞吐强，主打多并发 | [[vLLM]] |
| SGLang | — | 高性能引擎，擅长前缀复用与结构化生成 | [[SGLang 与 TensorRT-LLM]] |
| TensorRT-LLM | — | NVIDIA 官方深度优化引擎，性能上限高但编译部署重 | [[SGLang 与 TensorRT-LLM]] |
| MLX | — | 苹果官方机器学习框架，Mac 上硬件利用率高 | [[MLX 与 Apple 芯片推理]] |
| PagedAttention | — | vLLM 的核心技术，像虚拟内存一样分页管理 KV Cache | [[vLLM]] |
| 连续批处理 | Continuous Batching | 请求动态拼批，显著抬高吞吐 | [[vLLM]] |
| 前缀缓存 | Prefix Caching | 相同系统提示词/长文档的中间结果复用，省时间 | [[vLLM]] |
| 张量并行 | Tensor Parallel | 把一个模型切开到多卡上算，TP 数通常等于卡数 | [[vLLM]] |
| GPU 层卸载 | Offload / -ngl | 把前 N 层放 GPU、其余留 CPU，低显存跑大模型的关键旋钮 | [[llama.cpp 与 GGUF]] |
| FlashAttention | — | 优化注意力计算速度与显存的算法 | [[Attention 与 KV Cache]] |
| 投机解码 | Speculative Decoding | 用小模型猜、大模型验，提升生成速度 | [[推理性能指标与调优]] |
| 首字延迟 | TTFT | 从请求到出第一个 token 的时间，交互体验的关键指标 | [[推理性能指标与调优]] |
| 吞吐 | Throughput | 单位时间生成的 token 总量，多人共用看它 | [[推理性能指标与调优]] |
| 并发 | Concurrency | 同时处理的请求数，和显存、延迟互相拉扯 | [[推理性能指标与调优]] |
| 上下文溢出 | Context Overflow | 输入超过上下文窗口，表现为截断或报错 | [[上下文窗口与位置编码]] |
| 显存不足 | OOM | 显存装不下，最常见故障；先分权重太大还是上下文太长 | [[故障案例库]] |
| 显存碎片 | Fragmentation | 反复分配释放导致"明明有空间却分配失败" | [[故障案例库]] |
| OpenAI 兼容 API | OpenAI-Compatible API | 各家引擎都实现同一套接口，换引擎不用改上层代码 | [[OpenAI 兼容 API 规范]] |
