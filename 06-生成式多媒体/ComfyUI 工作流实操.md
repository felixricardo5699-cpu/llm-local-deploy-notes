# ComfyUI 工作流实操

> [!abstract] 一句话讲清楚
> 这篇讲"怎么从官方模板改出一条能交付的工作流"：换模型、改提示词、定分辨率、调采样、存图验收，最后把黑图、报错、形状不匹配这些现场问题按顺序排掉。

## 为什么重要

- 客户现场不会等你研究原理。你要能在 10 分钟内把一条模板改成"客户的数据能跑、效果能看"的流程。
- 90% 的 ComfyUI 故障不是模型坏了，而是**改错了某一处关联参数**：换了模型没换编码器、改了分辨率没改 latent、接了 ControlNet 没接图像输入。这篇就是把这些关联关系摆出来。
- 这一篇和 [[ComfyUI 核心概念]] 是一对：那边讲"节点是什么"，这边讲"改哪个、怎么验证、坏了怎么修"。先看概念再动手，效率差一倍。
- 交付场景里，你还要把"我们自己跑得通"变成"客户照图文能跑通"，验收清单是必须的。

## 核心名词全解

| 名词 | 英文 / 缩写 | 大白话解释 | 容易混淆 / 注意 |
|---|---|---|---|
| 官方模板 | Default / Example Workflow | ComfyUI 自带的示范工作流，打开就能跑 | 模板是"最小可运行"，不是"最好效果" |
| 另存工作流 | Save / Export | 把当前图存成 JSON 文件 | 要区分 UI 格式和 API 格式 |
| 模型槽 | Model Slot | 加载节点上选文件的下拉框 | 选中的是文件名，不是"某类模型" |
| 提示词权重 | Prompt Weighting | 用括号/数字提高某个词的影响力 | 语法随前端版本略有差异，先小范围试 |
| 正/负条件 | Positive / Negative | 想要的和不想要的 | 蒸馏模型常不认负向条件 |
| 空 latent | Empty Latent | 给定宽高的初始噪声 | 宽高改了等于换画布 |
| 批量大小 | Batch Size | 一次采样出几张 | 涨显存，不是"免费多出几张" |
| 种子策略 | Seed / Fixed / Random | 固定或每次随机 | 交付要固定，探索要随机 |
| 重绘蒙版 | Inpaint Mask | 标出"只改这里"的区域 | 蒙版要贴合，边缘会羽化 |
| 输出前缀 | Filename Prefix | 保存文件名前缀 | 带日期和场景，方便追溯 |
| 队列 | Queue | 待执行任务列表 | 排队时改参数影响的是下一次 |
| 报错节点 | Error Node | 执行失败被标红的节点 | 红的是"出错点"，根因常在它上游 |

## 原理与机制

### 一条最小工作流的骨架

不管模板长什么样，能出图的最小结构就五段：

**加载模型 → 编码提示词 → 造噪声 latent → 采样 → 解码保存。**

中间任何花活（LoRA、ControlNet、放大、修脸）都是往这五段之间"插节点"，插完必须保证数据流还连得上。判断一个工作流能不能用，就看这五段是否完整、每个输入口是否都有来源。

### 为什么"从模板改"而不是"从空白搭"

- 模板里已经处理好了一体化/分离式模型的加载方式、编码器类型、VAE 接线——这些是最容易接错的地方。
- 模板的默认参数是"安全值"，能出图；你只需要按需求微调，问题范围小。
- 从空白画布搭，你等于同时验证"接线对不对"和"参数对不对"，出问题分不清是谁。

### 参数之间的耦合关系

改一处常要连带改另一处，这是实操的核心认知：

| 你改了 | 必须连带检查 | 不改的后果 |
|---|---|---|
| 换模型（同架构） | VAE、采样器推荐值、CFG | 色偏、糊、参数不匹配 |
| 换模型（跨架构） | 编码器、VAE、latent 通道 | 黑图、形状不匹配报错 |
| 改分辨率 | 显存、构图、是否超训练分辨率 | 爆显存 / 双头 / 细节崩 |
| 加 ControlNet | 参考图输入、控制强度、预处理节点 | 完全没效果或画面被压死 |
| 加 LoRA | 触发词、权重、是否与底模同架构 | 没反应 / 画面污染 |
| 改步数 | 采样器类型（是否蒸馏模型） | 白花时间或糊图 |
| 改 CFG | 是否蒸馏模型 | 过曝、崩坏 |

### 出图链路的四个"可验收点"

1. **latent 前**：宽高是否正确、是不是 8 的倍数。
2. **KSampler 后**：如果预览是纯色/雪花，问题在采样参数或模型，别急着看 VAE。
3. **VAE Decode 后**：如果这里有图但发灰/偏色，问题在 VAE。
4. **保存后**：如果界面有图但文件没有，问题在保存节点路径/权限。

## 完整流程：从模板到交付

> 每一步都是"输入 → 动作 → 输出 → 验收标准"，验收不通过不要往下走。

| 步骤 | 输入 | 动作 | 输出 | 验收标准 |
|---|---|---|---|---|
| ① 起模板 | 官方默认工作流 | 打开后先原样跑一张，确认环境本身没问题 | 一张测试图 | 能出图且不报错，说明显卡、依赖、模型都在 |
| ② 另存 | 测试成功的工作流 | 立刻另存为带场景名的新文件 | 工作流 JSON | 文件名能看出用途和日期 |
| ③ 换模型 | 客户/项目要用的模型 | 在加载节点选对文件；跨架构时同步换编码器/VAE | 新模型对应的加载链 | 加载节点无红框，队列能跑到采样 |
| ④ 改提示词 | 业务描述 | 正向写"主体+动作+风格+画质"，负向写 3~5 个排除项 | 条件向量 | 出图主体正确、没有明显跑偏 |
| ⑤ 定画布 | 交付尺寸 | 设置宽高（接近模型原生分辨率），需要时加放大链路 | 初始 latent | 不爆显存，构图不重复 |
| ⑥ 调采样 | 质量/速度要求 | 步数、CFG、采样器、种子按场景定 | 干净 latent | 细节与提示词吻合，无过曝/糊 |
| ⑦ 解码保存 | 干净 latent | VAE 解码 + Save Image（或 Preview） | 图片文件 | 颜色正常、路径正确、文件名可追溯 |
| ⑧ 小批量验证 | 5~10 条真实提示词 | 批量跑一遍，看稳定性 | 批量结果 | 没有随机崩图，失败率可接受 |

### 第③步的细节：换模型到底要换什么

- **同架构换 ckpt**（比如都是 SDXL 类）：只换加载节点里的文件。VAE 一般能沿用，但出现偏色就换回模型自带 VAE。
- **跨架构换模型**（UNet 一代 → DiT 一代）：等于换整条链。加载节点、编码器类型、VAE、甚至采样参数全套换。**不要试图把旧模板的编码器接到新模型上。**
- **分离式模型**：主干、编码器、VAE 三个文件都要对上，缺一个就是黑图或报错。

### 第④步的细节：提示词怎么写才可控

- 结构推荐：`主体 + 细节/材质 + 环境/光线 + 风格 + 画质词`。先保证主体，再堆风格。
- 权重语法用来"救局部"：主体不够突出时加权重，但别全句加，不然等于全部加强=没加强。
- 负向提示词别写"不要模糊"，写"blurry"这类具体词；有的模型对负向条件不敏感，以实拍为准。
- 提示词顺序有影响：越靠前的词通常权重越高（尤其 CLIP 类编码器）。
- 中文提示词在中文原生模型上可用，在英文训练模型上常失效——外语提示词仍是默认安全选择。

## 排错手册：从现象到根因

> [!important] 排查铁律
> 先看**最后出错的节点**，再看它**上游有没有缺输入**，最后才怀疑模型文件。绝大多数"玄学"故障是接线或目录问题。

| 现象 | 先查什么 | 常见根因 | 处理 |
|---|---|---|---|
| 全黑图 | 模型链是否完整 | 编码器接错/缺失（Flux 类最常见）、VAE 不对、latent 通道不匹配 | 按官方模板逐口核对；换回模板模型验证环境 |
| 全灰/纯色图 | 采样参数 | CFG 过低、步数过少、denoise 过小 | 用模板默认参数复跑一张作对照 |
| 花屏/网格状噪声 | VAE | 解码分辨率过高、VAE 与模型不匹配 | 换回模型自带 VAE；高分辨率用 tiled 解码 |
| 报"shape mismatch / 尺寸不匹配" | latent 宽高 | 宽高不是 8 的倍数、批量维度对不上、图生图输入尺寸与 latent 不一致 | 宽高取 8 或 64 的倍数；检查批量和通道 |
| 爆显存 OOM | 分辨率与模型大小 | 分辨率过高、批量过大、没开分块 | 降分辨率/批量，换量化模型，开 tiled VAE |
| 红色 missing node | 自定义节点 | 插件没装/版本不兼容/装完没重启 | Manager 补装 → 重启 → 仍缺就找替代节点或重搭该段 |
| 控制节点没效果 | 控制输入 | ControlNet 没接参考图、强度为 0、预处理图全黑 | 先在预览里确认预处理输出是正常姿态/深度图 |
| 点运行没反应 | 队列/接线 | 输出节点没接、该分支未被依赖、队列卡住 | 检查是否连到 Save/Preview；重启后端清队列 |
| 界面有图、文件夹没有 | 保存节点 | 路径不存在、无写权限、前缀为空 | 改用绝对路径并确认权限 |
| 改了参数没生效 | 缓存/死分支 | 参数在不参与执行的分支上、队列里跑的是旧任务 | 确认连线是否连到输出；清缓存重跑 |
| 出图人物有双头/多手 | 分辨率 | 超过模型训练分辨率的构图外推 | 回到原生分辨率，再走放大流程 |
| 提示词明明写了却没出现 | 文本编码 | 提示词被截断、中文模型不匹配、编码器没接上 | 精简到前 40 个词；换英文；检查编码器连接 |

### 黑图排查的固定顺序

1. 换回官方模板和默认模型，能出图 → 说明环境没问题，问题在你的工作流。
2. 逐步替换：先换模型文件，再换编码器，再换 VAE，每次只动一处。
3. 用 Preview 节点看 KSampler 输出的 latent 解码预览：如果采样后就是纯色，问题在条件/参数；如果采样后有内容而最终黑，问题在解码/保存。
4. 检查日志：控制台会打印哪个节点抛异常，比界面红框信息多得多。

## 分类与对比：三种最常用的工作流

| 模板 | 起点 | 关键差异 | 典型需求 |
|---|---|---|---|
| 文生图 | 空 latent | 全靠提示词，参数最敏感 | 概念图、海报、电商主图 |
| 图生图 | 你的参考图 → VAE 编码成 latent | 多一个"重绘强度"控制改动幅度 | 风格迁移、草图渲染、保构图换风格 |
| 局部重绘 | 参考图 + 蒙版 | 只对蒙版区域采样，边缘要羽化 | 去水印、改产品、换衣服、修手 |

| 模板 | 要不要改动上游 | 常见坑 |
|---|---|---|
| 文生图 | 不需要 | 分辨率乱设、提示词太抽象 |
| 图生图 | 输入图尺寸要处理好 | denoise 太高变重画、太低没变化 |
| 局部重绘 | 蒙版必须同尺寸、涂准 | 蒙版全白=整图重画；羽化太小会留边 |

## 决策点

- **岔路口 1：从哪个模板开始**
  推荐：能对号入座就别自定义。文生图用默认模板，保构图用图生图模板，改局部用局部重绘模板。
  代价：模板自带参数未必最优，但先跑通再优化，比一上来调参稳。

- **岔路口 2：效果不对时先改提示词还是先改参数**
  判断：主体缺失/跑偏 → 改提示词；画面糊/过曝/没细节 → 改 CFG 与步数；构图比例不对 → 改分辨率。
  推荐：一次只改一类，固定种子，A/B 对比截图。同时改三处，你永远不知道是哪生效的。

- **岔路口 3：图生图 denoise 给多少**
  推荐：保主体换风格 0.35~0.5；大改但留构图 0.55~0.7；只是轻微修 0.25 左右。
  提醒：超过 0.8 基本等于重画，别指望它"保留原图"。

- **岔路口 4：单张精修还是批量出图**
  条件：客户要 1~3 张精品 → 单张 + 固定种子反复微调；
  条件：要几十上百张 → 先定一条稳定参数，固定下来再批量，别边出边改。

- **岔路口 5：出图慢，改哪里**
  顺序推荐：先换蒸馏模型 → 再降步数 → 再降分辨率 → 最后才考虑换硬件。直接砍步数通常是最差的一步。

## 参数与配置说明

| 参数 | 在哪改 | 作用 | 常见取值 |
|---|---|---|---|
| 宽 × 高 | Empty Latent | 画布尺寸，直接决定显存和构图 | 贴近模型原生分辨率，取 64 倍数 |
| 批量大小 | Empty Latent / KSampler | 一次出几张 | 低显存固定 1 |
| 步数 | KSampler | 去噪迭代次数 | 20~30（蒸馏 4~8） |
| CFG | KSampler | 文本贴合强度 | 5~7（蒸馏 1~1.5） |
| 采样器/调度器 | KSampler | 每步走法 | 与模型配套，别乱配 |
| 种子 | KSampler | 复现控制 | 交付固定，探索随机 |
| denoise | KSampler（图生图） | 重绘幅度 | 0.3~0.7 |
| 文件名前缀 | Save Image | 输出命名 | 项目名+日期 |
| 保存路径 | Save Image / 启动参数 | 输出目录 | 独立数据盘 |

## 一个完整例子：把产品图改成场景图

需求：客户给一张白底产品图，要 10 张"放在不同场景里"的图。

| 步骤 | 具体操作 | 为什么 |
|---|---|---|
| ① 选图生图模板 | 打开 image-to-image 模板 | 保产品形状，靠原图约束 |
| ② 接参考图 | Load Image 接到 VAE Encode，再进 KSampler | 原图变成 latent 起点 |
| ③ 定 denoise | 先给 0.45 试一张 | 太高产品会被改形，太低背景不变 |
| ④ 写场景提示词 | 正向写"场景 + 光线 + 材质 + 产品名"，负向写"变形、多余物体" | 场景描述越具体，随机性越小 |
| ⑤ 加蒙版（可选） | 只让背景区域重绘，产品区域不采样 | 产品完全不变形的稳妥做法 |
| ⑥ 固定种子做 A/B | 同种子只改提示词，找出最稳的描述结构 | 找出"能复用的提示词模板" |
| ⑦ 批量换场景 | 保留结构，只替换场景关键词，种子改为随机 | 批量生产靠模板不靠灵感 |

这个例子教会你一个通用思路：**先用一张图把参数锁定，再把"变量"限制在一个字段里**，批量才可控。

## 批量与参数化

- **界面批量**：KSampler 的 seed 设为 random，配合批量大小，一次出多张；适合先选图。
- **提示词批量**：把提示词外置成文本列表，逐条替换后跑。界面上手动改 100 次不现实。
- **API 批量**：用 API 格式导出工作流，脚本替换提示词字段，提交队列、轮询结果。这是接入客户系统的方式。
- **参数文件化**：把"尺寸、步数、模型名、提示词模板"抽成一份配置，工作流只读配置。交付后客户改配置就行，不用改图。
- **命名规范**：输出文件名带批次号、种子、提示词短标签，出问题能反查是哪条参数导致的。

> [!tip] 参数化的最小标准
> 客户能自己安全改的只有三样：提示词、出图张数、尺寸。其余全部锁死。这个边界必须在交付说明里写清楚。

## 现场 10 分钟排错流程

1. **2 分钟**：让他发界面截图 + 控制台最后 20 行日志，先定位是真故障还是操作问题。
2. **3 分钟**：让他切回官方默认工作流跑一张。能出图 = 他的工作流问题；不能出图 = 环境/硬件问题。
3. **3 分钟**：看报错节点的上游，重点查"模型文件在不在、编码器对不对、宽高是不是倍数"。
4. **2 分钟**：改一处、跑一张，别一次改五个地方。修不好就把版本号和模型清单要回来，在你自己机器上复现。

> 这套流程的本质是二分法：把"环境问题"和"工作流问题"先切开，再把"模型问题"和"参数问题"切开。

## 常见坑与误区

| 现象 | 原因 | 对策 |
|---|---|---|
| 换模型后出黑图，之前是好的 | 跨架构换了模型没换编码器/VAE | 换模型先确认"它需要哪几个配套文件"，按官方模板接 |
| 工作流在 A 机正常、B 机打不开 | 两边 ComfyUI 版本不同、插件不同 | 记录版本；交付前在目标版本上重跑一遍 |
| 装插件后整个 ComfyUI 启动报 import error | 插件依赖与主环境冲突 | 回退插件版本或换独立环境；交付机保持干净依赖 |
| 模型放在文件夹里但下拉框找不到 | 放错子目录、扩展名不对、文件名有中文 | 按目录约定放、改英文名、刷新或重启 |
| 明明改了提示词，图一点没变 | 改的是没接到输出的旧编码节点；或缓存分支 | 顺着线确认"我改的节点连到 KSampler 了吗" |
| 分辨率设 1024×1024 的模型，输出 1920 宽会重复 | 超训练分辨率外推 | 原生出图 + 放大链路，别一步到位 |
| 蒙版涂了但边缘有硬边 | 蒙版没有羽化/尺寸不一致 | 加大羽化、确认蒙版与图同尺寸 |
| 中文提示词全是乱码/无效 | 编码器/模型不支持中文文本 | 换中文原生模型，或统一用英文提示词 |

## 常用搭配速查

| 需求 | 模型方向 | 参数起点 | 备注 |
|---|---|---|---|
| 快速试构图 | 任意 | 12 步 / CFG 5 / Euler a | 分辨率减半 |
| 二次元出图 | SD 系二次元微调 | 25 步 / CFG 7 / DPM++ 2M | 负向词加 "bad hands" 一类 |
| 写实质感 | Flux / SDXL 类写实模型 | 25~30 步 / CFG 3~5 | 提示词写镜头与光线 |
| 中文文字/海报 | 中文原生或排版强的模型 | 按模型卡推荐 | 文字类提示词加引号强调 |
| 保产品换背景 | 图生图 + 蒙版 | denoise 0.4~0.6 | 产品区域用蒙版保护 |
| 低配机器 | 蒸馏版模型 | 4~8 步 / CFG 1~1.5 | 必须配套采样器 |

## 三个高频误区

- **把"参数调到极致"当本事**：客户要的是稳定出图，不是实验室参数。能复用的中规中矩，比一次惊艳更值钱。
- **用同一套参数通吃所有模型**：模型换了，步数、CFG、采样器全要重试。老经验只对同架构同系列有效。
- **只测好看的提示词**：真正的验收是拿客户最刁的业务描述去跑，那时候才会暴露提示词结构和分辨率的问题。

## 种子与复现的正确用法

- **探索阶段用随机种子**：同一句提示词出 4~8 张，挑构图最好的那张，记下种子。
- **精修阶段固定种子**：只改提示词或 CFG，观察单一变量的影响。
- **复现要一整套**：模型文件 + 编码器 + VAE + 采样器 + 步数 + CFG + 分辨率 + 种子，缺一个都可能不同图。
- **换机器不保证一致**：不同显卡/不同 PyTorch 版本可能算出一丁点差异，放大后肉眼可见。追求跨机一致要谨慎承诺。
- **客户演示前锁设置**：把种子、模型都固定，现场只改提示词，演示效果才稳。

## 工作流验收清单（交付前过一遍）

- [ ] 在干净环境里从零跑通，不依赖你机器上的隐藏配置。
- [ ] 模型、编码器、VAE、插件版本全部列成清单交给客户。
- [ ] 输入输出路径用绝对路径或统一相对路径，不指向你本机盘符。
- [ ] 提示词、尺寸、张数这三个客户会改的字段，加注释框标注。
- [ ] 用 5~10 条真实业务提示词批量跑过，失败率为 0 或可解释。
- [ ] 保存一张参数截图 + 一张效果图，写进操作说明。
- [ ] 客户能自己重启服务并恢复，不靠你远程。

## 性能基准怎么测

报价和方案都靠这三个数，别靠猜：

1. **单张耗时**：固定同一条工作流、同一张尺寸，连跑 5 张取平均（第一张含模型加载，要剔除）。
2. **峰值显存**：跑的时候看显卡监控，记录峰值，留 1~2G 余量给系统。
3. **连续稳定性**：连跑 30 张不出错、不越跑越慢，才算能交付。

> [!note] 这两个数写在报价单里
> "本机单张约 X 秒、峰值显存约 Y G"，客户一眼就知道方案边界在哪。写"很快/流畅"等于什么都没说。

## 快速问答：现场最常被问的四句

- **"为什么我改提示词没变化？"** 你改的节点多半没接到采样器，或者改的是另一条分支。顺着线看。
- **"为什么图比昨天糊？"** 先看是不是换了模型/VAE/采样器，再看步数和 CFG 有没有被谁改过。工作流要版本化就是为了回答这个问题。
- **"为什么同样的参数换台机器不一样？"** 模型文件、插件版本、显卡都可能不同。复现是"整套环境"，不是"几个数字"。
- **"能不能直接上 4K？"** 不能一步到位，走"原生分辨率出图 → 放大模型 → 局部精修"的链路，这也是标准的交付做法。

## 自检问题

- [ ] 一条最小可出图工作流的五段是什么，缺哪段会怎样？
- [ ] 为什么先跑官方模板再改？它验证了什么？
- [ ] 跨架构换模型时，哪些东西必须一起换？
- [ ] 出现"形状不匹配"报错，你先查哪个参数？
- [ ] 黑图的固定排查顺序是什么？
- [ ] 图生图的 denoise 和文生图的 steps 分别在控制什么？
- [ ] 界面有图但文件没保存，问题在哪？
- [ ] 怎么保证一条工作流交付到客户机器上还能跑？

> [!tip] 最后一句
> 工作流是"资产"，不是"操作记录"。跑通的那一刻就要另存、命名、留参数截图——这是专业和业余的分界线。

> [!note] 复杂工作流怎么读
> 从最后一个节点（保存图像）往回倒推：谁给它图 → 谁给它条件 → 它缺什么。倒着读比正着读快得多。
> 遇到报错先看报错的**节点标题**，不是节点类型名——标题是你自己起的，能直接定位。

## 交付视角（对客户怎么讲）

- 客户问"能不能改"：能，我们交付的是工作流文件，改提示词、换风格、加环节都不用重做，这是选这套方案的原因。
- 客户问"为什么出的图每次不一样"：生成有随机性，要稳定就固定种子；但批量生产更看重"风格稳定"而不是"像素一致"，这点要提前对齐预期。
- 客户问"卡了/黑了怎么办"：给他一张"三步自检卡"——先看模板能不能跑、再看模型文件在不在、最后把日志截图发你。这能挡掉大半远程支持。
- 报价时把"环境安装 + 工作流搭建 + 培训 1 小时 + 一个月排错支持"分开列，别打包成一个"AI 出图"，客户会按张数砍价。
- 交付文档里给一张"参数速查卡"（打印出来贴在工位旁），比十页手册有用。
