# 文生图模型生态

> [!abstract] 一句话讲清楚
> 文生图模型不是一个"越新越强"的排行榜，而是**架构代际 × 生态成熟度 × 显存成本 × 许可证**四者的权衡；选型的答案取决于你要画什么、在哪台机器画、给谁用。

## 为什么重要

- **选错底模，后面的活全白干。** LoRA 生态、ControlNet 生态、加速方案都是围绕底模长的；底模换了，配套资产全部作废。
- **"最新最强"不等于"最适合"。** 新架构通常显存要求更高、生态还没长齐，而老一代模型（SDXL 系）生态极厚，商用交付反而更稳。
- **许可证是硬门槛。** 同一个模型，个人玩和给企业做商用物料是两回事；选型时就要分清楚。
- **客户不关心架构，只关心"能不能达到我要的效果，多久，多少钱"。** 选型结论要能翻译成这三句话。

## 核心名词全解

| 名词 | 人话解释 | 在选型里的分量 |
|---|---|---|
| 底模（Base Model） | 基础大模型，决定整体能力与风格倾向 | 最高，一切生态围绕它 |
| 精调模型（Checkpoint） | 在底模上继续训练出的成品，如写实版、二次元版 | 高，直接决定出图观感 |
| LoRA | 几百 MB 的小补丁，加角色/画风/材质 | 高，定制化主力 |
| ControlNet | 用姿态、深度、边缘等条件控制构图 | 高，商用可控性的关键 |
| VAE | 负责把潜空间还原成像素 | 中，影响色彩与细节 |
| 文本编码器 | 把提示词变成模型能懂的条件 | 中，决定中文/长文本能力 |
| 采样器（Sampler） | 从噪声一步步去噪的算法 | 中，影响速度与质感 |
| CFG（提示词引导强度） | 多大程度"照提示词来" | 中，过高会崩、过低会飘 |
| 蒸馏加速模型 | 用更少步数出图的轻量版本（Turbo、Lightning 一类） | 中，批量出图必看 |
| 提示词遵循度 | 模型多大程度听懂复杂指令 | 高，商用场景的核心指标 |
| 架构代际 | UNet 一代 → DiT 类 → 原生多模态类 | 高，决定上限与显存 |
| 训练分辨率档位 | 模型在什么尺寸上训练的 | 中，超档位容易出双头 |

## 原理与机制

### 直觉版

文生图模型像一个"看过海量图文对的美术生"。你给它一句话，它从一团随机噪声开始，一点点把画面"雕"出来。底模决定这个美术生的功底和口味；精调模型是让他专门练过某类画风；LoRA 是临时塞给他一本参考画册；ControlNet 是给他一张线稿说"按这个构图画"。

### 拆解版：四代架构在争什么

| 代际 | 代表（系列级） | 核心变化 | 带来的后果 |
|---|---|---|---|
| 第一代 UNet 系 | SD 1.5 一代 | 潜空间扩散 + 交叉注意力注入文本 | 生态极厚，但分辨率与文本能力弱 |
| 第二代 UNet 放大系 | SDXL 系 | 双文本编码器、更大分辨率、更好的结构 | 1024 档位可用，商用主力，生态最全 |
| 第三代 DiT 类 | SD3/3.5 系、Flux 系、Qwen-Image 类 | 用 Transformer 替代 UNet，流匹配类训练 | 提示词遵循与文字渲染大幅提升，显存变高 |
| 第四代原生多模态类 | 各家闭源模型 | 文本、图像统一建模，支持对话式编辑 | 体验最好，但多为 API，不可本地化 |

两个关键机制值得记住：

- **文本条件的注入方式变了。** 老一代是"交叉注意力塞进去"，新一代是"文本与图像 token 一起进 Transformer"。后者导致长提示词、复杂空间关系、画面内文字都明显更好——这是新版模型最值得付费的差异点。
- **蒸馏加速改变了参数含义。** 加速模型通常要求 CFG 接近 1、步数极少（4~8 步）。此时你还按"步数 30、CFG 7"去跑，出来的是废图，不是模型不行。

### 后果：选型其实在选"生态"

真正决定你能不能交付的，往往不是模型本身，而是**它周围的配套**：

- 有没有成熟的 LoRA 训练工具与素材库？
- 有没有 ControlNet 全套（姿态、深度、边缘、分割）？
- 有没有被验证过的加速方案、量化版本？
- 社区里踩坑帖多不多（踩坑帖多说明用的人多，遇到问题能搜到答案）？

一个能力更强但生态荒漠的新模型，在交付项目里往往不如一个能力中等但生态成熟的模型。

## 分类与对比

### 按用途分

| 用途 | 首选方向 | 为什么 | 备选 |
|---|---|---|---|
| 写实人像/产品图 | SDXL 系精调模型、Flux 系 | 皮肤质感与光影成熟，LoRA 多 | 商用闭源 API 兜底 |
| 二次元/插画 | SD 系、SDXL 系精调 | 生态最厚，画风 LoRA 最多 | 新代写实模型转画风 |
| 电商海报（含文字） | 新代 DiT 类（文字渲染强） | 画面内文字是老大难 | 出图后排版软件补字 |
| 中文语义复杂提示 | Qwen-Image 类、新代国产模型 | 中文编码与语义理解更顺 | 英文重写提示词 |
| 批量跑图（几百张） | 加速模型 + 中低分辨率 | 单张速度是成本大头 | 老一代大模型 |
| 强可控（按图出图） | ControlNet 生态成熟的模型 | 没有控制网就无法交付商用 | 参考图类适配器 |

### 六维评分直觉

| 维度 | 老一代大生态 | 新一代强模型 | 闭源 API |
|---|---|---|---|
| 出图质量上限 | 中 | 高 | 高 |
| 提示词遵循度 | 中 | 高 | 很高 |
| 画面内文字 | 差 | 中到好 | 好 |
| 本地显存成本 | 低 | 高 | 零 |
| 生态配套（LoRA/控制网） | 极厚 | 逐步补齐 | 无（或受限） |
| 商用可控性 | 高（可本地） | 高（可本地） | 受条款与数据出境约束 |

### 同一模型的不同"档位"

同一个系列通常提供多个档位，别拿一个档位代表整个系列：

- **完整版**：能力最全，显存最贵，适合出成品。
- **蒸馏加速版**：步数少、速度快，适合批量与试稿，质量略降。
- **量化版**：fp8、gguf 等，为小显存准备，速度与质量有折损。
- **精调版**：社区在完整版上微调，画风更讨喜但可能过拟合。

### 系列速查（系列级，不含具体版本）

| 系列 | 代际 | 定位 | 适合 | 显存感受 | 生态 |
|---|---|---|---|---|---|
| SD 系（1.5 一代） | 一代 | 老牌万能 | 二次元、快速试验 | 很低，8G 很轻松 | 极厚 |
| SDXL 系 | 二代 | 商用主力 | 写实、插画、电商 | 中，8G 需量化 | 极厚 |
| SD3/3.5 系 | 三代 | 文字与遵循度升级 | 复杂提示、画面文字 | 偏高 | 中等 |
| Flux 系 | 三代 | 写实与指令遵循强 | 写实人像、产品、海报底图 | 高，需量化才能上小卡 | 厚 |
| Qwen-Image 类 | 三代 | 中文语义与文字渲染 | 中文海报、国风、电商 | 中高 | 成长中 |
| HunyuanImage 类 | 三代 | 国产开源强模型 | 中文场景、写实 | 高 | 中等 |
| 蒸馏加速系列 | 配套 | 少步数快速出图 | 批量试稿、实时预览 | 与底座同 | 依附底座 |
| 商用 API 类 | 四代 | 闭源顶级效果 | 质量兜底、小批量 | 零 | 无本地资产 |

### 生态周边清单

底模之外，一个可交付的图生成系统通常还要这些：

- **加速方案**：蒸馏模型、少步数采样器，决定批量成本。
- **LoRA 库**：角色、画风、材质，几十 MB 一个，是定制化的主力。
- **控制网全套**：姿态、深度、边缘、分割、参考图类。
- **放大与修脸**：出图后的质量补救链路，交付成片基本都过一遍。
- **工作流模板**：把上述组合固定成 JSON，是交付资产的核心。
- **提示词库**：按业务场景沉淀的提示词，比模型更能体现经验。

## 决策点

- **岔路口 1：8G 卡该选什么**
  推荐：**SDXL 系 + fp8/量化 + 1024 档位以下**，或者老一代 SD 系。不要硬上新代大模型，即使能跑也是分钟级一张。
  理由：8G 的核心矛盾是速度与稳定性，不是画质上限。

- **岔路口 2：12~16G 卡**
  推荐：**SDXL 系原生 + 新代模型的 fp8 版**并行装两套：老生态做可控交付，新模型做质量兜底。16G 可以把新代模型当主力。

- **岔路口 3：24G 及以上**
  推荐：**新代 DiT 类为主力**，fp16 原生跑，配加速方案做批量。老一代留着做 LoRA 快速试验，因为它快。

- **岔路口 4：客户要"最好看"还是"最可控"**
  最好看 → 新代强模型 + 精修；最可控 → 生态成熟模型 + ControlNet + LoRA + 固定种子 + 人工修图。**商用项目优先可控**，因为返工成本高于画质收益。

- **岔路口 5：本地还是 API**
  条件：数据不能出内网、量大、要长尾定制 → 本地；
  条件：质量要求最高、量小、不介意联网 → API 更划算。
  推荐：**能本地就本地**，API 作为质量兜底，两者不冲突。

- **岔路口 6：中文提示词还是英文**
  推荐：如果模型原生支持中文（新代国产系列），用中文；老一代模型用英文（或中译英），否则遵循度明显下降。团队里最好统一一种提示词语言规范。

## 完整流程：从候选到定稿

选型不是"看两篇评测就决定"，而是一个可以复制的流程：

1. **收需求**：要画什么（人像/产品/插画/海报）、有没有文字、要不要可控、谁用（内部还是客户）。
2. **拉候选**：按用途和显存筛出 2~3 个系列，每个系列选一个档位（完整/加速/量化）。
3. **做基准测试**：固定 10 条业务提示词、固定种子、固定分辨率，每个候选各跑一轮。
4. **打分**：一次通过率、需重试次数、单张耗时、显存峰值、可控性（能否用控制网复现构图）。
5. **定主备**：主力一个 + 备用一个，主力负责交付，备用负责兜底和风格差异。
6. **固化成模板**：把参数、模型、LoRA 顺序写成工作流 JSON，入库并写说明。
7. **验收**：用客户真实需求跑 20 张，统计命中率，作为交付标准写进文档。

> [!tip] 打分表长什么样
> 一行一个候选，五列：一次通过率 / 平均重试次数 / 单张秒数 / 显存峰值 / 可控性评分。不要凭印象选，印象会被最漂亮的那一张图带偏。

### 一个容易忽略的判据：重试成本

同样"能出好图"，模型 A 平均 1 次过、模型 B 平均 4 次才过，实际成本差 4 倍。对批量业务来说，**重试率比画质上限重要**。这也是为什么许多交付项目最终选了"看起来没那么惊艳但很稳"的老一代模型。

## 参数与配置说明

| 参数 | 典型范围 | 调法 |
|---|---|---|
| 分辨率 | 老一代 512 档、SDXL 系 1024 档、新代 1024 档以上 | 卡在训练档位附近，别乱跳 |
| 步数 | 常规 20~30；加速模型 4~8 | 加速模型别加步数，没用还变慢 |
| CFG | 常规 5~8；加速与蒸馏模型接近 1 | 先查模型卡推荐，别沿用上一代经验 |
| 采样器 | 常规用主流一两种即可 | 不同采样器差异小于"模型+提示词"的差异 |
| 负面提示词 | 老一代常用，新代常空 | 新代强模型给负面词反而干扰 |
| 种子 | 固定种子做对照测试 | 对比模型时必须固定 |
| 提示词长度 | 中短句、具体名词优先 | 堆形容词不如写清楚主体+场景+光线 |

## 常见坑与误区

| 现象 | 原因 | 对策 |
|---|---|---|
| 新模型装上但出图很糊/很慢 | 用了量化版却按完整版参数跑；显存不足触发换页 | 换 fp16 版对照；降分辨率；看显存峰值 |
| 加速模型出图崩坏、糊成一团 | 仍用高 CFG 与多步数 | 蒸馏模型 CFG 接近 1、步数 4~8 |
| 换新底模后 LoRA 全失效 | 跨代架构不兼容 | LoRA 必须与底模同代；重建素材重训 |
| ControlNet 完全没效果 | 控制模型与底模不同代 | 一套控制网只服务一代底模 |
| 画面出现双头、重复肢体 | 分辨率超出训练档位或比例极端 | 回到训练档位，极端比例用放大+裁切 |
| 提示词里"文字"总是乱码 | 老一代模型文本能力弱 | 换新代模型，或出图后用排版软件补 |
| 客户拿去商用被投诉 | 模型许可证禁止商用 | 交付前查模型卡 license，写进合同 |
| 同一提示词隔天效果不同 | 换过模型文件、插件版本、种子 | 工作流与模型版本一起入库 |

## 成本与速度的量级感

不给精确数字，只给能用来报价的量级：

| 场景 | 单张耗时量级 | 用途 |
|---|---|---|
| 8G 卡 + 量化新模型 + 1024 | 分钟级 | 试稿、单张定制，不适合批量 |
| 12~16G 卡 + fp8 新模型 | 几十秒 | 小批量、按需出图 |
| 24G 卡 + fp16 新模型 | 十几到几十秒 | 常规交付 |
| 24G 卡 + 加速蒸馏模型 | 几秒 | 批量试稿、抽卡、实时预览 |
| 老一代小模型 + 低分辨率 | 亚秒到几秒 | 快速构图验证 |

再乘两件事：**重试次数**（差的模型要抽 5 次才成）和**后处理时间**（放大、修脸、排版往往比出图更久）。给客户报价时，如果只算出图时间，一定会亏。

## 常见需求与推荐组合

| 客户需求 | 推荐组合 | 显存底线 | 说明 |
|---|---|---|---|
| 商品图批量出图 | SDXL 系精调 + 加速模型 + 放大 | 12G | 追求稳与快，不追极限画质 |
| 人像写真/肖像 | 新代写实模型 + 参考图适配器 + 修脸 | 16G | 一致性靠参考图，不靠抽卡 |
| 动漫插画/头像 | SD 系 + 画风 LoRA 大量 | 8G | 老生态在这里仍然能打 |
| 中文海报 | Qwen-Image 类等文字强模型 | 16G | 文字仍是短板，做好排版兜底 |
| 电商场景图（换背景） | 可控模型 + 分割 + 局部重绘 | 12G | 可控性优先于画质 |
| 快速概念草图 | 加速蒸馏模型 + 低分辨率 | 8G | 几十张里挑一张，再看细节 |

## 提示词语言与模型匹配

- **模型在什么语料上训的，就吃什么语言。** 老一代英文模型对中文提示词理解有限，中译英后效果通常更好。
- **新代国产系列对中文更友好**，但也不等于"随便说人话"，主体、场景、光线、风格四要素仍然要写全。
- **提示词不是越长越好。** 堆二十个形容词不如写清"是什么、在哪、什么光、什么风格"。
- **负面提示词要看代际。** 老一代靠负面词压畸形；新代强模型给太多负面词反而干扰，先空着试。
- **团队要统一语言规范**：同一项目里混用中英文提示词，结果不可比，也没法沉淀成资产。

## 模型迁移与兼容性

换模型时按这个顺序检查，能省掉大半返工：

1. **架构是否同代**：跨代就重来，LoRA、控制网全部重新配。
2. **分辨率档位是否变化**：新模型 1024 起，老参数 512 会出怪图。
3. **CFG 与步数是否被"继承"**：新代常要接近 1 的 CFG，老参数直接搬会崩。
4. **文本编码器是否变化**：分离式模型的编码器换了，提示词语感会变。
5. **VAE 是否配套**：偏色、糊、灰，先换回自带 VAE 对照。
6. **工作流节点是否有对应实现**：新架构可能要用新加载节点、新采样节点。

## 交付视角（对客户怎么讲）

- **不要报模型名，报能力。** 客户听不懂 SDXL 还是 Flux，他只想知道"能不能出我要的那种图、一张多久、能不能改"。
- **给三个方案。** 低成本（小显存+老生态）、推荐（中等显存+新模型）、顶配（大显存+精修链路）。让客户在预算和效果之间做选择，而不是替他决定。
- **主动说限制。** 手部、文字、多主体一致性是行业共同难题；提前说清楚，比交付后被挑刺强。
- **把模型选型写进方案文档。** 一句话说明"选它的理由 + 显存要求 + 许可证状态"，既显专业，也是后续报价的依据。
- **验收标准要量化。** 例如"固定 10 条业务提示词，8 条一次通过、2 条允许人工微调"，比"效果要好"可执行得多。
