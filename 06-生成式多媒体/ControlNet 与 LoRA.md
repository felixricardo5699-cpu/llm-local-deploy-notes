# ControlNet 与 LoRA

> [!abstract] 一句话讲清楚
> ControlNet 管"怎么摆"（构图、姿态、深度、边缘），LoRA 管"长成什么样"（风格、角色、材质）；前者是**外挂的条件注入**，后者是**权重上的小补丁**，用途完全不同，但经常一起用。

## 为什么重要

- **它们是文生图从"抽卡"变成"生产"的分界点。** 只会写提示词，交付靠运气；会用 ControlNet 和 LoRA，才能对客户说"这个构图能复现"。
- **商用场景几乎必然用到。** 产品图要固定摆位、人物要固定形象、画风要统一——这三件事分别对应控制网、LoRA、精调模型。
- **最容易配错的两类资产。** 控制网和 LoRA 都必须与底模同代，跨代直接失效；新手 80% 的"没效果"都出在这。
- **显存与复杂度会叠加。** 多个控制网叠加、多个 LoRA 叠加，都是显存与冲突的重灾区。

## 核心名词全解

| 名词 | 人话解释 | 注意什么 |
|---|---|---|
| ControlNet | 读取控制图、把结构信息注入主干的旁路网络 | 必须与底模同代 |
| 控制图 | 姿态骨架、深度图、边缘图等 | 要干净、要匹配目标构图 |
| 预处理器 | 从照片自动提取控制图的算法 | 提取器与控制网要配套 |
| 控制强度 | 控制信息影响的力度 | 太高会僵硬、太低无感 |
| 起止步 | 控制在生成的哪一段生效 | 常用于"先控结构后放风格" |
| 姿态控制 | 用人体骨架指定动作 | 人物类需求最常用 |
| 深度控制 | 用深度图指定空间层次 | 场景、产品摆位 |
| 边缘/线稿控制 | 用轮廓线指定形状 | 保留原图造型 |
| 分割控制 | 用色块图指定区域布局 | 大面积构图、室内 |
| LoRA | 加在模型上的低秩权重补丁 | 几十到几百 MB，与底模同代 |
| 触发词 | 激活 LoRA 效果的专属词 | 漏写就等于没加载 |
| LoRA 权重 | 补丁影响强度 | 常见 0.6~0.9，过高烧图 |
| 参考图类适配器 | 用图片提供风格/身份参考 | 与控制网不同，管的是"像谁" |
| 多控制网叠加 | 同时用两个以上控制条件 | 会打架，要调强度 |

## 原理与机制

### 直觉版

ControlNet 像给画师一张"结构草图"：你告诉他"人物摆成这个姿势、房间是这个透视"，他照结构画，但画风还是他自己的。LoRA 像给画师一本"参考画册"：他看完之后画的东西会带那本画册的味道，但结构还是随机的。

### 拆解版

- **ControlNet 的工作方式**：在主干旁边复制一份编码器并加上"零卷积"连接，训练时只让这份副本学"如何把控制图变成结构提示"。推理时把控制图喂进去，输出会按强度混进主干的中间特征。所以它**不改变模型风格，只改变结构倾向**。
- **起止步为什么有用**：生成前期决定构图，后期决定细节。让控制只在前 60% 的步数生效，就能"锁住结构、放开风格"，画面不会太僵硬。
- **LoRA 的工作方式**：在注意力层的权重旁挂两个低秩矩阵（A、B），只训练这两个小矩阵。推理时把它们的乘积按权重加到原权重上——所以它是"风格/概念的偏移量"，**改变的是画什么和画成什么样**。
- **为什么能叠、又为什么打架**：LoRA 的叠加是权重相加，多个补丁在同一处叠加会互相覆盖；控制网则是多个条件同时注入，条件之间可能矛盾（姿态说坐着、深度说站着）。

### 后果

- **想改构图 → 用 ControlNet；想改风格/身份 → 用 LoRA；想"照着这张图" → 参考图类适配器。** 选错工具怎么调都没用。
- **控制网越多不等于越准。** 两个条件冲突时，画面会变成"四不像"，比单条件更差。
- **LoRA 不是万能的定制方案。** 需要极高还原度、大量姿态变化时，微调模型或训练专属 LoRA 才是正解。

## 分类与对比

### 常用控制类型

| 控制类型 | 控制图长什么样 | 适合 | 常见坑 |
|---|---|---|---|
| 姿态（OpenPose 类） | 彩色骨架点线 | 人物动作、舞蹈、多人摆位 | 手部骨架不准 |
| 深度（Depth 类） | 灰阶远近图 | 场景、产品空间关系 | 深度图过曝或全灰 |
| 边缘（Canny 类） | 黑白线条 | 保留原图轮廓 | 线太密导致画面发灰 |
| 线稿（Lineart 类） | 干净线稿 | 上色、二次元 | 与边缘控制混用 |
| 分割（Seg 类） | 彩色色块 | 大布局、室内、换背景 | 色块类别要对应 |
| 法线（Normal 类） | 蓝紫渐变 | 立体感、材质 | 少见，效果不稳 |
| 平铺/放大（Tile 类） | 原图本身 | 高清放大、补细节 | 强度过高会糊 |
| 参考图类 | 一张参考照片 | 风格/身份相似 | 与 LoRA 定位不同 |

### LoRA 的类型

| 类型 | 作用 | 典型训练量 | 使用要点 |
|---|---|---|---|
| 风格 LoRA | 画风、质感 | 几十张图 | 权重中低，太高会盖掉提示词 |
| 角色 LoRA | 固定人物/吉祥物 | 十几到几十张 | 必须写触发词 |
| 材质/元素 LoRA | 特定物件、纹理 | 几十张 | 与提示词配合 |
| 姿势/构图 LoRA | 特定构图套路 | 几十张 | 容易与提示词冲突 |
| 概念 LoRA | 抽象风格、字体 | 视情况 | 触发词敏感 |
| 加速 LoRA | 少步数出图 | 训练产物 | 与加速底座搭配，不改风格 |

## 完整流程

### 用 ControlNet 复现一个构图

1. **定需求**：要控制的是"姿态"还是"布局"？姿态用骨架，布局用分割/深度。
2. **准备控制图**：客户照片 → 预处理提取骨架；或自己画一张结构示意。
3. **选对控制网**：确认它属于哪个底模代际（SDXL 系有 SDXL 系专用控制网，不能混用）。
4. **接线**：加载控制图节点 → 控制模型加载节点 → 接入采样器的控制输入；强度先给中间值。
5. **跑一张**，对比"结构像不像、风格是否被压住"。
6. **调参**：结构不够硬 → 提高强度；画面僵硬 → 降低强度或缩短控制步范围。
7. **叠加第二条件**（可选）：先加"必须"的那个，再加辅助条件，强度各降一点。

### 用 LoRA 统一画风

1. 确认底模：LoRA 训练在哪个底模上，就用在哪个底模上（同代才有效）。
2. 加载节点接到模型加载之后，权重先 0.8。
3. 提示词里加触发词，位置不重要但要写。
4. 试三档权重（0.6 / 0.8 / 1.0），看风格强度与画面崩坏。
5. 检查提示词是否被盖掉：风格太重时，主体描述会失效。

### 训练一个 LoRA（简化版）

1. 收数据：同一主体 15~40 张，多角度多表情，清晰无遮挡。
2. 清洗：去掉低质量、重复、带别人的图。
3. 打标：每张写清楚"有什么、不是什么"，加入触发词。
4. 训练：小批量、适度轮数，中途出样检查过拟合。
5. 验收：用 10 条不同提示词测试，看是否"只在触发时生效、不影响其他内容"。
6. 交付：权重文件 + 触发词 + 推荐参数 + 示例图。

> [!tip] 训练数据的铁律
> **数据质量比数量重要一个量级。** 20 张干净图训出来的 LoRA，比 200 张杂图稳定得多。

## 决策点

- **岔路口 1：用 ControlNet 还是直接写提示词**
  条件：客户能接受每次构图随机 → 提示词就够；
  条件：构图/姿势必须固定 → 必须上 ControlNet。
  推荐：批量生产、要做模板的，直接上控制网。

- **岔路口 2：ControlNet 还是参考图适配器**
  想控"结构/姿势"→ ControlNet；想控"像某个风格/某张脸"→ 参考图适配器或角色 LoRA。
  容易搞混的点：拿照片当参考图想控制构图，是典型的用错工具。

- **岔路口 3：用现成 LoRA，还是自己训**
  条件：风格接近现有资源 → 现成的先用；
  条件：客户品牌形象、吉祥物、固定角色 → 自己训。
  推荐：**先搜现成、再决定训**，训一个 LoRA 的时间成本不低。

- **岔路口 4：多个控制网怎么排**
  推荐顺序：姿态/布局这类"硬结构"在前，边缘/细节在后，强度从高到低；数量别超过 2~3 个。
  条件：两个条件冲突 → 保留一个，退化成提示词描述。

- **岔路口 5：LoRA 权重给多少**
  风格类 0.6~0.8，角色类 0.8~1.0；超过 1.0 基本是烧图。
  条件：多 LoRA 叠加 → 每个都降 0.1~0.2。

- **岔路口 6：8G 显存能不能用**
  能，但要注意：控制网本身有开销，多控制网叠加更吃显存；LoRA 开销小。低显存优先用轻量控制类型（边缘/线稿），少叠。

## 参数与配置说明

| 参数 | 典型范围 | 调法 |
|---|---|---|
| 控制强度 | 0.5~1.0 | 先 0.7 试，结构不够再加 |
| 控制起止步 | 全段 / 前 60%~80% | 后期放开可减少僵硬 |
| 预处理分辨率 | 与目标出图接近 | 太低提取不准 |
| 预处理阈值（边缘） | 中低到中高 | 线太密画面发灰，调低 |
| LoRA 权重 | 0.6~1.0 | 过高盖提示词、烧图 |
| 触发词 | 每个 LoRA 自带 | 漏写=效果打折 |
| 控制图数量 | 1 张为主 | 多个要同构图 |
| 采样步数 | 20~30 | 控制生效需要一定步数 |

## 常见组合配方（可直接抄）

| 需求 | 组合 | 关键参数 |
|---|---|---|
| 固定人物姿势、换服装 | 姿态控制 + 角色 LoRA | 控制 0.7 / LoRA 0.85 |
| 产品图保形状、换背景 | 边缘或分割控制 + 重绘 | 控制 0.8 / 局部去噪 0.6~0.75 |
| 室内大布局重绘 | 分割（色块）+ 边缘 | 先分割 0.9，再边缘 0.5 |
| 线稿上色 | 线稿控制（不要用边缘） | 控制 0.9，提示词只写颜色材质 |
| 老照片修复/放大 | 平铺控制 + 分块放大 | 平铺权重 0.4~0.5，别太高 |
| 多角色同框 | 分割 + 姿态各一 | 控制数别超 2，强度各 0.6 |

三个"别"：

- 别把边缘和线稿叠加，它们抢的是同一件事，只会互相削弱。
- 别在控制图里画得太细，模型会照抄所有瑕疵。
- 别指望控制网解决"像谁"，那要靠参考图适配器或角色 LoRA。

## 显存开销与性能

- 单个控制网额外占一份编码器权重，通常比主干小很多，但**激活峰值会涨**。
- 两个以上控制网叠加，显存与耗时都明显上去，8G 卡很容易爆。
- LoRA 本身开销小，但多个 LoRA 叠加时要额外算注意力权重，不是零成本。
- 预处理（提骨架、算深度）也有显存开销，批量跑时容易被忽略。

## 常见坑与误区

| 现象 | 原因 | 对策 |
|---|---|---|
| 加了 ControlNet 完全没效果 | 控制网与底模不同代 / 接线没连到采样器 | 换匹配版本，检查连线与启用开关 |
| 控制图提取出来全黑或反色 | 预处理参数错、原图太暗 | 换预处理类型，先看预处理预览 |
| 画面僵硬、像贴图 | 控制强度太高、全程生效 | 降到 0.6~0.7，起止步收窄 |
| LoRA 加载了但风格没变 | 底模不匹配 / 忘写触发词 | 换同代底模，补触发词，权重加到 0.9 试 |
| 多个 LoRA 一起用画面崩 | 权重叠加冲突 | 逐个降权、分开测试 |
| 预处理器与控制器不配套 | 提取的是线稿却接了姿态控制网 | 让"预处理输出类型"与"控制网类型"一一对应 |
| 自定义节点版本冲突导致工作流打不开 | 控制网/预处理器插件更新后节点定义变了 | 锁插件版本，交付环境固定，备份工作流 JSON |
| 控制网模型放错目录，列表里找不到 | 不同插件有各自的 models 子目录约定 | 按插件文档放，别全塞一个目录 |
| 训练出的 LoRA 背景总是串味 | 训练集背景太单一 | 数据里混入多样背景，打标写清背景 |

## 自检问题参考答案

> [!success]- 1. ControlNet 和 LoRA 改变的东西有什么本质区别？
> ControlNet 是外挂的条件注入：它读控制图，按强度把"结构倾向"混进主干特征，不改模型权重，所以改的是构图、姿势、空间关系。
> LoRA 是权重上的低秩补丁：推理时把补丁乘积加到注意力层权重上，改的是画什么和画成什么样，也就是风格、身份、材质。
> 一句话：控制网管怎么摆，LoRA 管长什么样；一个作用于输入条件，一个作用于权重。

> [!success]- 2. 为什么控制网必须与底模同代？
> 因为控制网是在某一代主干上训练的，它的侧分支要和主干的中间特征维度、层数、位置对齐。
> 换一代模型（比如 SD 系换到 SDXL 系或 DiT 系），主干结构变了，控制网注不进去：轻则完全没效果，重则直接报形状错误。
> 所以 SDXL 系只能用 SDXL 系控制网，不能混用；换代时整套控制网资产都要重新准备。

> [!success]- 3. 起止步是干什么用的，什么时候该收窄？
> 它控制结构条件在生成的哪一段生效。生成前期定构图、后期定细节，让控制只在前 60%~80% 的步数生效，就能锁住结构、放开风格，画面不至于僵硬得像贴图。
> 所以画面僵硬、风格被压死时收窄起止步；反过来结构总跑偏、需要全程锁死时才放到全段。
> 它比单纯降控制强度更精细，两个参数通常配合着调。

> [!success]- 4. 想固定人物脸和想固定姿势，分别该用什么？
> 固定脸用参考图类适配器或角色 LoRA，它们管的是"像谁"；固定姿势用姿态控制网，它管骨架。
> 常见错误是拿一张照片当参考图想控制构图——参考图类适配器只提供风格或身份相似，不保证姿势复现。
> 两件事都要就姿态控制加角色 LoRA 一起上，控制强度各降一点，别都拉到满。

> [!success]- 5. 多控制网叠加时最大的风险是什么？
> 最大的风险是条件互相矛盾：姿态说坐着、深度说站着，模型只能折中，画面变成四不像，比单条件更差。
> 第二个风险是显存与耗时明显上涨，8G 卡很容易爆。
> 对策是数量别超过 2~3 个：先加必须的那个，再加辅助条件，强度各降一点；两个条件冲突就保留一个，另一个退化成提示词描述。

> [!success]- 6. LoRA 没效果时先查哪三件事？
> 一查底模是否同代，跨代 LoRA 加载了也不起作用；二查触发词有没有写进正向提示词，漏写等于没加载；三查权重够不够，先加到 0.8~0.9 试。
> 都正常还不生效，再确认文件放对目录、加载节点确实接在模型链上。
> 顺序别乱：底模、触发词、权重，这三条覆盖九成的"没反应"。

> [!success]- 7. 训练 LoRA 时数据的"干净"指什么？
> 三件事：画面干净（清晰、无遮挡、无低质量噪点）、背景干净（别太单一，否则模型把背景当特征学进去）、内容干净（不混别人的图、重复图、带水印的图）。
> 每张还要打标写清"有什么、没什么"，并把触发词写进标注。
> 数据质量比数量重要一个量级：20 张干净图训出来的，比 200 张杂图稳定得多。

> [!success]- 8. 8G 显存下怎么用控制网最稳？
> 优先轻量控制类型，比如边缘、线稿这类，数量控制在 1 个，别叠加。
> 强度从 0.6~0.7 起步，起止步收窄到前 60%~80%，预处理分辨率别开太高，能明显降激活峰值；LoRA 开销小，可以配一个。
> 两个以上控制网在 8G 上基本会爆，要上就降分辨率或走分块；总之这一档是"能用但要克制"。

## 交付视角（对客户怎么讲）

- **把"可控"翻译成客户听得懂的话**：不是"我用了 ControlNet"，而是"你把这张照片给我，人物姿势和产品摆位都能按它来，换背景也行"。
- **先做一版"能复现的模板"再谈量产**：控制网 + LoRA + 固定参数 = 可复现流水线，客户最认这个。
- **明确风格上限**：LoRA 是"像"不是"是"，承诺"100% 还原 IP 形象"要么加训练预算，要么改用精调模型。
